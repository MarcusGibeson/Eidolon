# Eidolon Development Roadmap: v1501.3 to v2500

Status at drafting: v1501.2 is installed and has completed four consecutive supervised-development cycles, including one after restart. The loop can discover structural candidates, create bounded proposals, prepare isolated workspaces, implement and verify candidates, stop for operator installation, reconcile completion, and continue without duplication.

This roadmap is directional, not a promise that version numbers alone create intelligence. A milestone advances only when its behavioral acceptance gate passes. Concrete defects discovered in daily use may insert narrow repair releases without changing the destination.

## Ownership Legend

- **MOBILE-BROWSER CAMPAIGN**: The default owner. Browser ChatGPT may continue through many adjacent versions and subsections from one current source-only ZIP. Work remains portable, isolated, tested, cumulative, and unpromoted.
- **BROWSER-CHECKPOINT**: A recoverable cumulative save with hashes, manifests, tests, and a work ledger. It is not an automatic Codex review or handoff.
- **DESKTOP-GATE**: A sparse, operator-invoked Codex session for genuinely local evidence, integration, installation, repair, or certification. Planned gates occur at 100-version era boundaries, with exceptions only when local work cannot safely be deferred.
- **DEFERRED-LOCAL**: Browser implements portable code, fixtures, documentation, and simulated validation now; Windows, native-provider, private-runtime, migration, security-authority, or installation evidence is accumulated for the next Desktop gate.
- **EIDOLON**: Eidolon can perform this through her supervised local cycle once the relevant discovery and verification capabilities exist. Active-source installation remains governed by the configured authority policy.
- **OPERATOR**: Marcus supplies preferences, subjective quality judgments, authority decisions, acceptable-risk policy, and real daily-use evidence.

Legacy section labels such as `WEB-BULK`, `SHARED`, and `CODEX-LOCAL` describe technical dependencies, not handoff cadence. The expanded roadmap translates them into the campaign model above.

## Delivery Rules

1. Browser work should run as one long campaign across adjacent roadmap sections. It should save recoverable artifacts every 20-30 minutes, but those saves do not end the campaign or require Codex.
2. Each saved candidate must contain one `Eidolon/` root, source-only files, a SHA-256, changed-file manifest, cumulative test results, known failures, deferred-local items, and a resumable work ledger.
3. Routine version, `.9`, 25-version arc, and midpoint checkpoints do not require Desktop Codex review. Browser may repair, retest, document, and continue through them.
4. The default planned Desktop cadence is once per 100-version era at v1600, v1700, v1800, v1900, v2000, v2100, v2200, v2300, v2400, and v2500, only when Marcus asks to run the gate.
5. Eidolon may independently perform read-only inspection and reversible isolated development. Installation, promotion, model management, secret access, destructive commands, and authority expansion remain separate decisions until later policy milestones explicitly change them.
6. Operator trials remain mandatory for conversation, personality, emotion, usability, trust, interruption burden, and willingness-to-continue gates. Automated prose scoring cannot substitute for Marcus.
7. Every initiative must state the observed problem, evidence provenance, expected benefit, acceptance criteria, risk, rollback path, and why it outranks alternatives.
8. “Tests passed” is not enough. Each arc must demonstrate an observable capability, reliability, usability, or maintainability improvement.
9. Trigger an early Desktop exception only for a concrete Windows/native failure, installation or migration need, security/authority change that cannot remain uninstalled, source drift or merge conflict, unrecoverable verification blocker, private-runtime defect, or explicit operator request.
10. If local evidence can wait, record it in the deferred-local ledger and continue Browser work. Do not stop merely because a future Desktop test will eventually be needed.

## Recommended Working Rhythm

- **Mobile Browser campaign**: continue through a full 100-version era when practical, completing portable implementation, fixtures, documentation, repair, and cumulative source-only saves.
- **Browser save point**: create a resumable ZIP and ledger after meaningful completed work or before timeout risk; then continue from that artifact without waiting for Codex.
- **Desktop gate**: batch the era's accumulated changed-file review, Windows/native evidence, deferred-local items, repairs, integration, installation, and benchmark work into one Codex session.
- **Eidolon trial**: run the new capability using real local runtime state and collect content-free receipts plus operator observations.
- **Operator decision**: install, reject, revise, defer, or roll back.
- **Checkpoint cadence**: Browser-only internal checkpoints as often as needed; no routine Codex midpoint reviews; one optional operator-invoked Desktop gate per 100-version era.
