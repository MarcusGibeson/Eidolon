# v1200.3 Ordinary-Chat Development Campaign Bundle Review

## Scope

Implemented only v1200.1-v1200.3 from the immutable, Desktop-verified v1200.0 source baseline.

## Functional result

Ordinary conversation now creates or resumes one persistent supervised development proposal for requests such as “Build me a to-do webpage.” The proposal stores private request and target data only beneath the external runtime root while exposing a content-free digest projection to conversation and dashboard surfaces.

The lifecycle supports exact revision-bound approval, exactly-once approval consumption, duplicate and multi-tab deduplication, cross-process intake locking, restart restoration, stale-save and stale-approval rejection, cancellation, rejection, interrupted-state reconciliation, approval-receipt integrity blocking, generation-safe request revision, and understandable unsupported-request states. Development lifecycle turns do not contact the configured provider and do not start implementation.

A digest-only intake index keeps revised wording attached to the correct proposal without exposing request text, project identifiers, project names, session identifiers, or private paths. Ordinary-chat intake also records action-shaped unsupported requests, including browser extensions, mobile applications, Eidolon-source modification, and model-management requests, rather than allowing them to fall back to ungrounded conversation.

## Findings

- Critical: none found.
- High: none found.
- Medium: grounded project inspection, specification, file planning, and test planning remain deferred to v1200.4-v1200.6.
- Medium: general provider-generated structured code and strict output validation remain deferred to v1200.7-v1200.9.

- Low: unsupported-scope classification is intentionally conservative and will need expansion as v1201-v1205 adds websites, JavaScript tools, and Python command-line implementation support.

## Boundaries

No provider generation, implementation, workspace creation, command execution, selected-project mutation, Eidolon source mutation, model installation/deletion/pull/replacement, release promotion, certification, or independent authority occurs in this bundle. The existing calculator alpha remains a separately approved regression path.


## Verification contract

The focused deterministic stage is registered in both bounded `quick` and `full` release profiles as `v1200.3-ordinary-chat-development-campaign`; this bundle runs only the focused stage and the bounded quick profile. The stage covers ordinary-chat classification, persistent create/resume, revision-safe intake indexing, exact revision and digest approval binding, exactly-once consumption, thread and process races, refresh/restart recovery, valid and invalid interrupted receipts, cancellation/rejection, stale controls, unsupported requests, dashboard rendering and narrow layout, a live digest-only proposal API request, source immutability, external runtime separation, and the retained calculator benchmark.

Candidate packaging must exclude runtime data, private request text, project metadata, conversations, memories, prompts, provider payloads, credentials, approval receipts, intake indexes, private paths, caches, and prior archives. The candidate is review-only and does not alter the installed v1200.0 baseline.
