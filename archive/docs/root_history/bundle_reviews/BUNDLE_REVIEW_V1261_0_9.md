# Eidolon v1261.0-v1261.9 Bundle Review

## Objective

Complete Evidence-Based Project Inspection as the first post-Coding-Alpha self-development evidence layer. The arc must inspect a project without granting work-selection or mutation authority, distinguish evidence from inference/assumption/unknowns, preserve contradictions, and remain bounded by the established v1254 privacy/path rules.

## v1261.0-v1261.2 — Foundations

Added `evidence_based_project_inspection_foundations.py`.

- Reuses v1254 project-root resolution, private/excluded-path rules, symlink/reparse rejection, portable Windows path validation, content hashing, and project adapter detection.
- Raises the read-only evidence inventory budget for complete project assessment while keeping a hard 5,000-file / 64 MiB bound.
- Produces structural architecture, test, documentation, configuration, syntax, maintenance-marker, and limitation-marker evidence without retaining raw source text.
- Introduces four explicit epistemic claim classes: `observed`, `inferred`, `assumed`, and `unknown`.
- Records runtime health, operator feedback, executed-test outcomes, and development-session history as unknown unless explicit evidence is supplied.
- Creates no proposal, backlog item, priority decision, execution authority, application authority, or self-modification authority.

## v1261.3-v1261.5 — Integration

Added `evidence_based_project_inspection.py`.

- Accepts explicit content-minimized evidence for runtime health, tests, operator feedback, known limitations, development-session state, and environment state.
- Normalizes external evidence to status codes and digests before inclusion.
- Replaces only the matching `unknown` claim when explicit evidence exists.
- Preserves supporting and contradicting evidence for the same claim as an unresolved `unknown` contradiction rather than silently choosing a side.
- Produces a sealed structured project assessment and minimized public projection.
- Rejects tampered assessment digests and unsupported external evidence kinds.

## v1261.6-v1261.8 — Reliability and Windows hardening

Added `evidence_based_project_inspection_reliability.py`.

- Rechecks source-manifest freshness and closes stale inspections.
- Rejects case-insensitive path collisions.
- Rejects symlink/link escapes and inherits native reparse-point rejection from v1254.
- Exercises >220-character project paths.
- Proves deterministic duplicate assessment output.
- Rejects unsupported evidence classes and tampered assessment records.
- Adds read-only health inspection and a Desktop Codex handoff focused on native Windows filesystem and concurrency realities.

## v1261.9 — Checkpoint

Added `evidence_based_project_inspection_checkpoint.py` and its checkpoint test. The checkpoint is source-discovered, read-only, content-minimized, and performs no provider call, command execution, test execution, runtime-state read, project mutation, backlog generation, or release action.
