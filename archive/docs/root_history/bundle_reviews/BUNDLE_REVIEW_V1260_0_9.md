# Eidolon v1260.0-v1260.9 Coding Alpha Checkpoint Review

## Scope

v1260 is the integration milestone for the supervised coding capabilities built in v1254-v1259. It does not add a new mutation authority. It proves that an ordinary calculator-webpage request can traverse the existing governed stages as one coherent campaign.

## v1260.0-v1260.2

- Added `coding_alpha_checkpoint_foundations.py` with one canonical calculator-webpage scenario and thirteen ordered stages.
- Bound the scenario to the existing owners for conversation, proposal approval, isolated execution, diagnostic repair, complete-application quality, persistent sessions, controlled application, and controlled rollback.
- Required an intentional failed quality attempt and one evidence-backed repair in the canonical evidence campaign.
- Required project immutability until exact application authorization and exact pre-apply restoration after separately authorized rollback.
- Explicitly denied provider, command, test, project/source mutation, application, rollback, installation, promotion, certification, release, permanent approval, and independent authority at the v1260 contract layer.

## Authority boundary

The v1260 layer composes evidence, not authority. Proposal approval, isolated execution, selected-project application, and rollback remain distinct exact contracts owned by their existing stages. Generic language such as “go ahead” never substitutes for any of those authorities. Installation, promotion, certification, release, permanent approval, and independent self-development authority remain denied.
